# 0004 文章分页、按年归档与文章导航

- 状态：已采纳
- 日期：2026-11-01
- 相关：[../architecture.md](../architecture.md)、[../../CONSTRAINTS.md](../../CONSTRAINTS.md)、[0003](0003-posts-section-and-article-component.md)

## 背景

站点只有一篇文章时，`/posts/` 直接列出全部文章就够用。写作模块要解决的是“文章多了也不乱”，可站点既没有标签与分类（见 [0003](0003-posts-section-and-article-component.md)），也还没有归档和文章之间的前后关系：列表会无限变长，旧文只能靠滚动找，读完一篇也没有下一站。

Hugo 自带分页与日期分组，满足这些需求不需要前端依赖，也不新增第三方请求。问题只剩决定放哪、放多少、入口在哪。

## 决定

- 文章列表分页，每页 8 篇，配置写在 `hugo.toml` 的 `[pagination] pagerSize`；只用服务端渲染，不做 JS 增强或无限滚动。
- 归档页放 `/archives/` 一级路由，按年倒序分组；`content/archives/_index.md` 设 `outputs: ["html"]`，归档只产出 HTML。
- 文章页脚显示“最后更新”（仅当 `lastmod` 与 `date` 不同）与上一篇/下一篇；上一篇 = 更早（`.PrevInSection`），下一篇 = 更新（`.NextInSection`）。
- 归档入口放页脚导航与 `/posts/` 列表页尾部，主导航保持“文章 / 关于 / 联系”三项。

## 替代方案

- 归档放 `/posts/archives/` 或 `/archive/`：前者层级更深，后者与仓库里的归档目录 `archive/` 容易混淆；一级路由 `/archives/` 在 sitemap 和链接里最清楚。
- 主导航加“归档”：390 px 宽度下四个中文导航项会挤，而归档是低频入口，页脚足够。
- 沿用 Hugo 默认的每页 10 篇：每页篇数固定写进配置，8 是版面可读性与页数的折中；改数字要同步改检查脚本里的契约常量，不适合随手调。
- 用标签/分类替代归档：要新增 taxonomy 页并持续维护标签，当前规模用不上（0003 已决定不启用）。

## 后果

- 文章超过一页时 `/posts/` 会生成 `/posts/page/<n>/`，其中 `/posts/page/1/` 只是指向 `/posts/` 的别名。分页页不进 `sitemap.xml`，“每个 index.html 都要进 sitemap”的检查必须排除它们。
- 列表、归档、上下篇都要有检查，否则改模板时可能悄悄丢文章：`check.py` 因此增加分页结构、归档覆盖、邻居链与最后更新四项检查，并在“生产构建只有一篇文章”时自适应通过。
- 归档页没有 RSS；页脚多一个入口，移动端页脚会多占一行。
- 文章顺序仍由 `date` 决定；同一天多篇时，上下篇的相对顺序不作为契约，检查脚本只校验链的结构一致性。

## 重新评估的时机

- 文章多到翻页成本明显上升时，再评估标签、系列或按年索引。
- 需要改每页篇数时，同步更新 `hugo.toml`、`scripts/check.py` 的契约常量与本文档，并新写一条 ADR 取代本条，不直接改历史。
