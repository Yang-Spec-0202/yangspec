# 0005 站内文档栏目：路径、入口与布局

- 状态：已采纳
- 日期：2026-11-04
- 相关：[../architecture.md](../architecture.md)、[../../CONSTRAINTS.md](../../CONSTRAINTS.md)、[0003](0003-posts-section-and-article-component.md)、[0004](0004-pagination-archive-and-post-navigation.md)

## 背景

站点原来只有按时间写的文章：列表按日期倒序，读完一篇靠上一篇/下一篇继续。但有些内容不是“某天写下的东西”，而是需要反复查阅、可以直接从某一节开始读的说明：这个站怎么读、正在做的项目是什么、发现问题怎么反馈。放进文章会被时间线越推越远，也没有固定导航。

仓库根目录已经有一份 `docs/`，但它是维护者文档：架构、ADR、发布与故障处理，读者不需要也不应该看到运维细节。因此站内文档不能直接搬用这份目录，需要一个新的、面向读者的内容 section。

## 决定

- 路径用 `/docs/`，源文件在 `content/docs/`。与仓库维护者 `docs/` 同名但位置不同：站内文档进构建、进 sitemap；维护者 `docs/` 不参与构建，也不出现在 `public/`。
- 主导航加“文档”，变成四项（文档、文章、关于、联系）；页脚也加“文档”入口。窄屏主导航两行断点从 380 px 提高到 430 px：390 px 下四项会换两行，但没有横向溢出；430 px 以上单行。
- 桌面 ≥1024 px 三栏：侧栏 / 正文 / 页内目录。761–1023 px 两栏，右栏隐藏、页内目录折叠到正文上方；≤760 px 单栏，桌面侧栏整块换成 `<details>` 折叠，页内目录折叠放在正文上方。折叠只用原生 `details`，不写 JS，键盘可以展开和收起。
- 侧栏与移动端折叠共用同一份链接列表，列出全部文档页与“文档总览”入口，当前页用 `aria-current="page"` 高亮。
- 页内目录由 `.Fragments.Headings` 生成两级（h2 + h3）；不用 `.TableOfContents` 输出两次，避免重复 `id="TableOfContents"`。文档总览不显示页内目录。
- 文档页之间用“上一节 / 下一节”（按 `weight` 升序），首末页不输出多余邻居；文章仍用“上一篇 / 下一篇”。Hugo 在 weight 升序 section 里 `.NextInSection` 指向更轻（更靠前）的一页、`.PrevInSection` 指向更重（更靠后）的一页，模板里“上一节”用 `.NextInSection`、“下一节”用 `.PrevInSection`，不要按字面交换。
- 文档关闭 RSS：`content/docs/_index.md` 设 `outputs: ["html"]`，不生成 `/docs/index.xml`；文档也不分页，不生成 `/docs/page/<n>/`。
- 内容范围先放四篇：文档总览、怎么读这个站、exam-grading 项目概览、纠错与反馈。文章栏目保持“按时间写下的东西”的定位。
- 文档总览与正文复用文章的 `article.html`、`page-header.html` 组件和既有样式变量，不引入第二套页面骨架。

## 替代方案

- 把仓库 `docs/` 搬到站内：受众不同，维护者文档含发布、回滚等运维细节，不对外；搬上去还要维护两套读者预期，不如分开。
- 用文章 section 承载文档：文章按时间倒序，稳定说明会被时间线埋掉，也没有固定侧栏和页内目录。
- 单页长文 + 锚点：内容一多就难找，移动端滚动成本高；多页 + 侧栏更适合反复查阅。
- 用 JS 手风琴或站内搜索：无 JS 时正文、导航、目录仍可用是既有约束；先不做搜索，`details` 折叠够用。
- 文档也开 RSS 或分页：文档不按时间更新，RSS 没有意义；正文只有几篇，分页只会多出入口和需要排除的页面。

## 后果

- 主导航从三项变四项，390 px 会换两行；页脚、sitemap 与检查脚本都要覆盖新路由。
- `check.py` 新增文档栏目检查：总览页存在、正文页至少 3 篇、没有 `/docs/page/`、每个文档页在 sitemap 里、侧栏覆盖全部文档页与总览入口、上一节/下一节与 `weight` 顺序一致；生产构建只有 3 篇正文时也要通过。
- `check-docs.py` 的 `public/docs` 语义改变：它现在由 `content/docs/` 合法生成，检查从“存在即失败”改成“维护者 `docs/` 的结构没有进入构建”（不得出现 `adr/`、`ops/`、`architecture.html`、`README.html` 等）。
- `preview-check.sh` 从七条路由增加到九条，补 `/docs/` 与 `/docs/exam-grading/`。
- 代价：两套 `docs/` 同名，容易放错位置；架构文档与 `docs/README.md` 必须写清边界。新增或调整文档页时要同步维护 `weight` 顺序，否则上一节/下一节检查会失败。
- 重新评估的时机：文档多到侧栏放不下、需要分组或二级导航时；需要搜索或版本文档时；移动端 `details` 折叠被证明不够用时。
