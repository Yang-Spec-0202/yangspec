`exam-grading` 是我在做的一个教师侧单机桌面应用：教师录入参考答案和评分规则，批量导入学生作业，由本地程序完成识别、对齐、判分、复核与导出。这篇只写概览；细节和进度以仓库为准。

## 做什么

- 参考答案与评分规则的录入：手写规则由模型整理成结构，**教师确认**后才生效，也可以套用现成的模板；
- 批量导入学生作业：纸质拍照或扫描、电子文档，文件名即学生身份；
- 本地完成识别、页面与题目区域对齐、两层判分（标准与快速两种模式）、人工复核与成绩导出；
- 默认离线；云端推理默认关闭，只在具体任务上逐次授权后启用。

## 不做什么（第一版明确排除）

学生端、账号与权限、局域网或服务端同步、在线考试、自动出题、非数学学科的判分实现、成绩单 PDF、应用签名与分发打包。判分依据始终是教师提供的参考答案与评分标准；没有参考答案时，模型不能凭空生成标准。

## 现在到哪一步

规范已经冻结（`SPEC` v0.2 系列、12 份模块规范与配置文档），仓库目前处于 M0 工程骨架阶段：workspace、13 个空 crate、CI 与文档骨架就位，业务模块尚未实现。进度以仓库 README 和提交记录为准，这里不提前宣布完成度。

## 技术选择

- 语言：Rust，edition 2024，stable；
- 界面：Slint；
- 存储：SQLite（单写连接 + WAL）加 BLAKE3 内容寻址的资产库，迁移只追加；
- 并发：标准线程、有界通道与 CPU 线程池，不引入 async 运行时；
- 推理：本地 sidecar 默认离线，另有 OpenAI 兼容的云端后端；模型按角色注册，过许可门禁。

## 数据与隐私

默认全部本地处理；云端推理默认关闭、按任务授权。原图按内容哈希只读保存，日志与诊断包脱敏；API Key 只从环境变量或系统钥匙串读取，不入库、不入日志。这些设计写进了规范，也由代码门禁约束。

## 许可与源码

项目整体以 **GPL-3.0-only** 发布（不含 “or later”）；界面框架 Slint 按其 GPL-3.0-only 分支使用；第三方依赖的许可由 `deny.toml` 白名单和 `cargo deny check` 把关，未列入白名单的许可默认拒绝。
